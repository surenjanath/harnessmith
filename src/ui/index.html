How it works

    
The solver model attempts the goal with the project's base harness (system prompt, guardrails, memory, tool guidance, skills, sub-agents, scripts, hooks). The improver model reads those attempts and proposes harness edits along two dimensions: how the agent works (INV) and what a practitioner knows (DOM). Each edit is probed with a fresh attempt, and a composer merges what the evidence supports. The selector then picks the best final output without seeing which harness made it, and writes a lesson into the project library for the next goal. Budget per goal: 4k solver runs and 3k improver sessions.

Doctor

    
Checks everything around a run (storage, Python, every model the roles use, cached failed rollouts, interrupted or stuck runs, temp files, each project's base harness, local servers) and fixes what it safely can. Safe fixes also run on their own at startup and every 10 minutes.

    

    

  

  

    
What heals itself

    
    
      
  • Model failover: give a role a chain, e.g. local/qwen2.5-7b, openai/gpt-4.1-mini. A failing endpoint trips a circuit breaker after 3 errors and calls move to the next model; when the cooldown ends, the primary is tried again. If every model is down, the agent waits for the first to recover instead of failing.
    • 
      
  • Agent self-checks: the same call returning the same result 3 times → "change approach"; 4 failing calls in a row → "re-read the errors"; budget nearly gone with nothing written → "deliver now". Tool calls written as text, or with broken JSON, are repaired.
    • 
      
  • Rollouts and runs: a rollout that errors is retried once; a run that fails or ends partial because of a model or transport failure is retried, reusing everything already finished; runs interrupted by a restart resume automatically.
